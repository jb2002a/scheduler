# 왜 자율형 에이전트로 설계했는가

이 프로젝트는 고정된 라우터 구조가 아니라 자율형 에이전트로 설계했다.
기능적으로 더 뛰어나서가 아니라, **사용자가 시간표를 짜는 방식에 더 자연스럽게 맞추기 위해서**다.

## 사용자는 정해진 순서대로 말하지 않는다

시간표를 짜는 학생은 처음부터 조건을 정리해서 말하지 않는다.
"수요일은 쉬고 싶은데, 아침은 좀 여유롭게, 근데 자료구조는 꼭 들어야 해"처럼 생각나는 대로 말하고, 결과를 보면서 마음을 바꾼다.
"아, 이거면 금요일이 너무 빡빡하네. 그냥 수요일에 하나 넣어도 돼."

고정 구조는 이런 대화를 미리 정한 흐름에 맞춰 처리한다. 흐름에 맞지 않는 말이 나오면 사용자가 다시 말하거나, 원하는 것을 시스템이 이해하는 형태로 바꿔서 말해야 한다.
자율형 에이전트는 사용자가 말하는 방식에 맞춰 다음 행동을 정한다. 사용자가 시스템에 맞추지 않고, 시스템이 사용자에게 맞춘다.

## "불가능합니다"에서 대화가 끝나지 않게

원하는 조건을 모두 만족하는 시간표가 없을 때, 사용자에게 필요한 것은 불가능하다는 판정이 아니라 다음에 무엇을 할 수 있는지다.
자율형 에이전트는 어떤 조건을 조금 완화하면 가능한지 직접 시험해보고, "주 4일로 늘리거나, 수요일에 한 과목만 듣는 방법이 있어요"처럼 선택지를 제시한다.
사용자는 어떤 조건 때문에 막혔는지 스스로 추측하며 이것저것 바꿔볼 필요가 없다.

## 물어볼 때와 알아서 할 때

모든 것을 되물으면 대화가 번거롭고, 모든 것을 알아서 처리하면 사용자가 원하지 않은 결과가 나온다.
"영어회화"와 일치하는 과목이 두 개일 때, 새 조건이 이미 정한 과목과 충돌할 때, "아침"이 몇 교시까지인지 애매할 때 되물을지 알아서 처리할지는 상황에 따라 다르다.
자율형 에이전트는 이 판단을 맥락에 맞게 내려서, 꼭 필요할 때만 사용자에게 묻는다.
되묻기는 `ask_user` 도구 호출로 구현해서, 언제 물었고 언제 묻지 않았는지가 기록에 남고 측정된다. 되묻는 횟수에는 상한을 둔다.

## 자율성은 판단에만, 정확성은 코드가

자율성이 UX를 위한 것이라면, 그 때문에 결과의 신뢰성을 잃어서는 안 된다.
그래서 에이전트에게는 무엇을 시도하고 무엇을 물어볼지만 맡기고, 다음은 코드가 보장한다.

- 시간표는 오직 솔버가 만든다.
- 사용자의 조건은 사용자가 요청할 때만 바뀐다.
- 탐색 단계와 비용에는 상한을 둔다.

사용자는 자유롭게 말하고, 결과는 항상 정확하다. 이것이 이 설계가 목표로 하는 경험이다.
