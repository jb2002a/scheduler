# 마일스톤과 우선순위

`DESIGN.md`의 10장(개발 순서)을 기준으로, 의존 관계와 위험도를 반영해 우선순위를 다시 정리했다.
`DESIGN.md`는 설계의 기준 문서로 그대로 두고, 이 문서는 **무엇을 어떤 순서로 만들지**만 다룬다.

## 1. 우선순위 원칙

1. **정확성의 바닥부터 만든다.** 파서, 데이터, 검증기가 틀리면 그 위의 솔버, 에이전트, UI가 모두 틀린다.
2. **여러 곳에서 재사용되는 것을 먼저 만든다.** 시간 파서와 검증기는 베이스라인 실험, 솔버 테스트, 에이전트 평가에 모두 쓰인다.
3. **불확실한 가정은 일찍 검증한다.** 실제 데이터가 설계 가정과 다르면 뒤로 갈수록 수정 비용이 커진다.
4. **UI는 마지막에 붙인다.** 에이전트가 CLI에서 정확히 동작한 다음에 화면을 얹는다.

## 2. 데이터 확인에서 드러난 설계와의 차이

`data/데이터베이스.md`를 확인한 결과, 설계(`DESIGN.md` 3장)의 가정과 다른 점이 있다. M0에서 정리했다.

| 항목 | 설계의 가정 | 실제 데이터 | 영향 |
|---|---|---|---|
| 형식 | CSV / 엑셀 | 마크다운 표 (전공·교필·교기·교선 섹션별로 컬럼이 다름) | 별도 변환 스크립트 필요 |
| 규모 | 약 100개 | 약 326행 (교선이 대부분) | 베이스라인 E1·E2 결과와 `search_courses` 존치 판단이 달라질 수 있음 |
| 필드 | 구분, 과목명, 학점, 시간 | 학기, 구분, 학수번호, 과목명(국문 / 영문), 학점, 이론, 실습, 강의시간 | `semester`, `course_code` 컬럼 추가 필요 |
| 학기 | 언급 없음 | 1학기 / 2학기 과목이 섞여 있음 | 카탈로그는 1학기만 사용한다. `1, 2` 과목은 1학기 행만 남긴다 |
| 구분 값 | 전공필수, 전공선택 등 예상 | `교필`, `교기`, `교선`, `기전`, `선전` | `credits` 조건의 `category` 매핑 규칙 필요 (예: "전공" = `기전` + `선전`) |
| 중복 행 | 없음 | 전공 표와 교양필수 표에 같은 학수번호가 중복 (예: L00002) | `course_code` 기준으로 중복 제거 |
| 시간 없음 | 없음 | 졸업논문 등 `-` (0학점, 시간 없음) | 파서가 `-`를 허용하고, 솔버 후보에서는 제외하거나 별도 처리 |
| 시간 표기 | `1` 뒤 `0`은 10교시 | 확인한 범위에서 10교시 표기 없음, `월12수1`처럼 한 요일에 여러 교시가 붙음 | 파서 규칙 자체는 유효. 전수 파싱 테스트로 확인 |
| 데이터 성격 | 실제 시간표 | 문서 설명상 학점에 맞춰 **임의로 배정한 시간표** | 실제 개설 정보가 아니므로 실사용 전에 실제 데이터로 교체해야 함 |

## 3. 의존 관계

```mermaid
flowchart LR
    M0[M0 데이터 기반<br/>파서 · 정제 · 검증기] --> M1[M1 베이스라인 실험]
    M0 --> M2[M2 솔버 단독]
    M1 -.->|결과로 구조 조정| M3
    M2 --> M3[M3 에이전트 연결]
    M3 --> M4[M4 UI]
    M3 --> M5[M5 평가 · 안정화]
    M4 --> M5
    M5 --> M6[M6 MVP 이후]
```

실선은 선행 필수, 점선은 결과를 보고 설계를 조정하는 관계다.

## 5. 우선순위 요약

| 순위 | 마일스톤 | 상태 | 이유 | 대략적 비중 |
|---|---|---|---|---|
| P0 | M0 데이터 기반 | 완료 | 모든 단계의 선행 조건, 설계와 데이터의 차이 해소 | 작음 |
| P0 | M2 솔버 단독 | | 정확성 보장의 핵심, 가장 큰 기술 위험 | 큼 |

| P1 | M3 에이전트 연결 | | 사용자 경험의 핵심 | 큼 |
| P1 | M5 평가 | | 구조가 실제로 낫다는 증거 | 중간 |

## 6. 지금 결정이 필요한 사항

| 항목 | 기본안 | 결정 시점 |
|---|---|---|
| 구분 코드 → `category` 매핑 | "전공" = `기전` + `선전`, "교양" = `교필` + `교기` + `교선` | M0 |
| 시간 없는 과목(`-`) 처리 | 후보에서 제외하고 필요하면 `course` 조건으로만 별도 표시 | M0 |
| 베이스라인 모델 두 종류 | 사용자가 보유한 API 기준으로 확정 | M1 시작 전 |
| `search_courses` 존치 | M1 결과로 결정. 그때까지 도구로 유지 | M1 종료 |
| 실제 개설 데이터 확보 시점 | M5 이전에 확보하는 것을 권장 | M3 중 |
